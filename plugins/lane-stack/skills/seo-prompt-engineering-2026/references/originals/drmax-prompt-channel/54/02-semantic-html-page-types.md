# Скил: логика семантической разметки по типам страниц

## Как использовать этот файл

Этот файл задает page-type specific правила. Его задача — не повторять общую теорию, а адаптировать семантическую стратегию под тип страницы, ее интент, модель извлечения фактов и типичные точки роста для ранжирования.

Для каждого типа страницы нужно оценивать:

- основную сущность страницы,
- основной интент пользователя,
- какие блоки являются primary facts,
- какие блоки являются narrative/context,
- какие блоки являются secondary noise,
- какие semantic patterns обязательны,
- какие нестандартные приемы дадут прирост в извлекаемости.

## Коммерческие страницы

| Тип страницы | Основная роль | Базовый semantic skeleton | Обязательные/сильные теги | Упущенные возможности и лучшие приемы |
|---|---|---|---|---|
| Главная страница | Презентация бренда и входная навигация | `main` + hero `section` + ключевые навигационные `nav` + блоки преимуществ/категорий | `header`, `main`, `nav`, `section`, `h1`, `ul`, `article`, `footer` | Не перегружать главную бессмысленным маркетингом; выделять ключевые входы в категории и услуги как самостоятельные смысловые блоки; брендовые обещания выносить в краткие fact-like секции. |
| Категория каталога | Листинг товарной группы | `main` + intro `section` + grid/list из `article` | `main`, `section`, `article`, `h1`, `h2`, `nav`, `ul/ol`, `aside` | Каждая карточка должна быть самостоятельной сущностью; фильтры и пояснения не должны смешиваться с листингом; полезно выделять секцию “как выбрать” и “популярные атрибуты”. |
| Подкатегория каталога | Узкий сегмент внутри раздела | как у категории, но с более узкой entity-frame | `main`, `article`, `section`, `nav`, `dl` | Сильнее выражать отличительный признак сегмента в intro и top facts; не делать дубль категории без семантического уточнения. |
| Страница фильтра (посадочная) | Пересечение характеристик под НЧ-интент | `main` + intro + filtered listing + explanatory sections | `main`, `article`, `section`, `dl`, `aside`, `nav` | Важно явно показать, по каким атрибутам сформирована выборка; useful pattern — top `dl` с “Тип”, “Материал”, “Бренд”, “Диапазон”, “Назначение”. |
| Страница товарной подборки | Тематический ручной список товаров | `main` + intro + curated list из `article` | `main`, `article`, `section`, `ol/ul`, `figure`, `h1/h2` | Полезно объяснять логику отбора; можно давать короткие reason blocks для каждого товара; не маскировать подборку под обычную категорию. |
| Страница бренда | Каталог товаров марки + бренд-контекст | `main` + брендовый intro `section` + listing из `article` | `main`, `section`, `article`, `figure`, `address`, `nav` | Вынести отдельные секции “О бренде”, “Преимущества бренда”, “Линейки”, “Сертификаты”; брендовые атрибуты можно упаковать в `dl`. |
| Категория бренда | Марка внутри конкретного раздела | `main` + intro + listing | `main`, `article`, `section`, `nav`, `dl` | Нужно явно обозначить двойную ось страницы: категория + бренд; избегать чистого дубля страницы бренда и чистого дубля категории. |
| Карточка товара | Детальная товарная сущность | `main` + `article` + локальный `header` + media + facts + detail sections | `article`, `header`, `figure`, `figcaption`, `dl`, `section`, `time`, `button`, `aside`, `footer` | Top facts panel через `dl`; разделение primary specs и marketing copy; отзывы как вложенные `article`; важные условия, совместимость и ограничения — отдельные citation-friendly секции. |
| Страница сравнения товаров | Сопоставление моделей | `main` + intro + comparison `table` + supporting sections | `table`, `caption`, `thead`, `tbody`, `th`, `article`, `section` | Нельзя заменять table на div-grid; полезно давать краткий summary до таблицы и отдельные секции “ключевые отличия”, “кому какая модель подходит”. |
| Страница услуги | Коммерческое предложение услуги | `main` + `article`/hero + facts + process + scope + proof | `article`, `section`, `dl`, `ol`, `blockquote`, `time`, `button` | Особенно сильны секции “Что входит”, “Что не входит”, “Сроки”, “Формат работы”, “Этапы”, “Кому подходит”, “Ограничения”; SLA/сроки/формат — в `dl`. |
| Категория услуг | Группировка смежных предложений | `main` + intro + list из service `article` | `main`, `section`, `article`, `nav`, `ul`, `aside` | Каждая услуга должна иметь собственный value proposition; полезны блоки выбора услуги и сценарии применения. |
| Прайс-лист (тарифы) | Табличное сравнение стоимости | `main` + intro + pricing `table` или список тарифных `article` | `table`, `caption`, `th`, `td`, `article`, `dl`, `time` | Если данные двумерные — использовать table; если тарифы самостоятельны — дополнительно размечать каждый как `article`; условия тарифа и ограничения — в `dl`. |
| Калькулятор стоимости | Интерактивный расчет | `main` + explanatory `section` + `form` + result block | `form`, `fieldset`, `legend`, `label`, `input`, `select`, `output`, `button`, `aside` | Расчет не должен быть “черным ящиком”; полезно семантически оформить параметры, ограничения, допущения и примеры результатов. |
| Страница акций | Список предложений со скидками | `main` + promo intro + discounted item list | `article`, `time`, `section`, `figure`, `dl` | Важно явно размечать срок действия, условия акции и состав исключений; old/new price логично сопровождать смысловым контекстом. |
| Программа лояльности | Условия для постоянных клиентов | `main` + overview + tiers/conditions | `section`, `ol/ul`, `dl`, `table`, `time`, `article` | Уровни программы можно оформлять как `article`; критерии и привилегии — через `dl` или `table`; временные условия — через `time`. |
| Корзина | Оформление выбранных товаров | `main` + cart form + line items | `main`, `form`, `article`, `ul/ol`, `button`, `fieldset`, `output` | Не рассматривать как purely technical page: line items должны быть читаемыми сущностями; сумма, доставка, скидки и ограничения должны быть явными. |
| Личный кабинет покупателя | Персональное рабочее пространство | `main` + account navigation + entity sections | `main`, `nav`, `section`, `article`, `form`, `time` | Лучше разбивать по задачам: профиль, заказы, адреса, подписки, бонусы; историю заказов оформлять как список самостоятельных сущностей. |

## Информационные и медиа-страницы

| Тип страницы | Основная роль | Базовый semantic skeleton | Обязательные/сильные теги | Упущенные возможности и лучшие приемы |
|---|---|---|---|---|
| Главная страница блога | Хаб инфоконтента | `main` + hero/topic intro + list из post `article` | `main`, `article`, `section`, `nav`, `time`, `figure` | Должна быть ясна логика навигации по темам; полезны блоки “последние”, “популярные”, “серии”, “руководства”, но без смешивания с основным листингом. |
| Рубрика | Тематический раздел статей | `main` + intro + post list | `article`, `time`, `section`, `nav` | Сильна intro-секция с объяснением темы рубрики и scope; статьи должны иметь повторяющуюся semantic structure. |
| Информационный тег | Узкая выборка материалов | `main` + tag intro + list | `main`, `article`, `section`, `nav` | Важно не оставлять страницу тега “пустой”; полезен контекст: что объединяет материалы по тегу, как он соотносится с рубриками. |
| Информационная статья | Экспертный контент | `main` + `article` + local `header` + sections | `article`, `header`, `section`, `h1-h3`, `figure`, `blockquote`, `ol/ul`, `time`, `aside`, `footer` | Для цитирования важны четкие headings, definition blocks, proof blocks, takeaway-lists; автор и дата должны быть машиночитаемыми. |
| Гайд | Большой пошаговый материал | `main` + `article` + page-nav + sequential sections | `article`, `nav`, `ol`, `section`, `figure`, `details`, `time` | Сильны page-nav, numbered steps, prerequisites, pitfalls, checklists; один огромный текст без секций — плохой вариант. |
| Обзор (хаб) | Большой разбор темы | `main` + `article` + thematic sections | `article`, `section`, `h2/h3`, `table`, `dl`, `blockquote` | Полезно разделять definition, comparison, scenarios, limitations, recommendations; comparison-блоки лучше делать table, а не div-карточками. |
| Новость | Актуальное событие | `main` + `article` + header + factual body | `article`, `header`, `time`, `figure`, `blockquote`, `footer` | Особенно важны дата, источник, статус обновления, временной контекст; полезна секция “что это значит”. |
| FAQ | Ответы на частые вопросы | `main` + intro + faq items | `section`, `article`, `details`, `summary`, `dl`, `h2/h3` | Короткие ответы — `details`; длинные и самостоятельные — `article`/`section`; полезно давать прямой ответ в первых строках каждого пункта. |
| Документация | Технические руководства и схемы | `main` + `article` + page-nav + reference sections | `nav`, `section`, `code`, `pre`, `kbd`, `samp`, `var`, `ol`, `table`, `dl` | Семантическое разделение кода, команд, вывода и параметров критично; FAQ-кусочки, параметры и терминологию удобно выносить в `dl`. |
| Словарь (глоссарий) | Толкование терминов | `main` + glossary list | `dl`, `dt`, `dd`, `dfn`, `article`, `nav` | Один из лучших типов страниц для `dl`; можно группировать термины по буквам/темам; полезны секции “связанные термины” и “пример употребления”. |
| Страница инфографики | Визуальный медиаконтент | `main` + media `figure` + explanation sections | `figure`, `figcaption`, `section`, `article`, `ul`, `table` | Важные факты из инфографики дублировать текстом; caption должен объяснять, что на инфографике и как ее читать. |
| Страница видеогалереи | Подборка видео | `main` + intro + list из video `article` | `article`, `figure`, `figcaption`, `time`, `section` | Каждое видео — отдельная сущность; полезны summary, тема, длительность, дата, для кого полезно. |

## Страницы доверия и авторитетности (E-E-A-T)

| Тип страницы | Основная роль | Базовый semantic skeleton | Обязательные/сильные теги | Упущенные возможности и лучшие приемы |
|---|---|---|---|---|
| О компании | История и ценности бизнеса | `main` + brand `article`/sections | `article`, `section`, `figure`, `blockquote`, `address`, `time` | Сильны блоки “кто мы”, “миссия”, “этапы развития”, “факты о компании”; timeline можно оформлять как `ol`. |
| Контакты | Официальные способы связи | `main` + contact sections | `address`, `section`, `nav`, `figure`, `time`, `form` | Контактные данные должны быть явно отделены от формы; филиалы можно оформлять как самостоятельные `article`. |
| Доставка и оплата | Логистика и расчеты | `main` + topic sections | `section`, `dl`, `ol`, `table`, `time`, `details` | Условия, сроки, регионы, способы оплаты и исключения должны быть структурированы; особенно полезны citation-friendly секции “Сроки”, “Стоимость”, “Исключения”. |
| Гарантии и возврат | Правила защиты покупателя | `main` + policy sections | `section`, `dl`, `ol`, `time`, `blockquote`, `details` | Важно выделять прямые ответы и ограничения; юридически значимые формулировки можно оформлять отдельными blockquote/sections. |
| Отзывы о компании | Социальное доказательство | `main` + list из review `article` | `article`, `blockquote`, `time`, `footer`, `figure` | Каждый отзыв как самостоятельная сущность; полезно отделять модераторские ответы; не смешивать отзывы с кейсами. |
| Сертификаты и лицензии | Доказательство соответствия | `main` + list из credential `article`/`figure` | `article`, `figure`, `figcaption`, `dl`, `time` | Хорошо работают карточки документа с типом, номером, сроком, кем выдано; визуальный скан обязательно дополнять текстом. |
| Портфолио (кейсы) | Коллекция результатов | `main` + intro + list из case `article` | `article`, `section`, `figure`, `dl`, `time` | Каждый кейс должен иметь явный outcome; полезны мини-метрики и отраслевой контекст. |
| Отдельный кейс | Подробный разбор проекта | `main` + case `article` + structured sections | `article`, `header`, `section`, `dl`, `figure`, `blockquote`, `ol`, `time` | Сильны секции “Задача”, “Контекст”, “Что сделали”, “Результат”, “Срок”, “Инструменты”, “Ограничения”; quick facts panel через `dl`. |
| Вакансии | Список актуальных позиций | `main` + list из vacancy `article` | `article`, `time`, `section`, `nav`, `aside` | Вакансии не должны быть просто ссылками; полезно кратко показывать роль, локацию, формат и seniority уже в списке. |
| Конкретная вакансия | Подробное описание роли | `main` + vacancy `article` + sections | `article`, `header`, `section`, `ul`, `dl`, `time`, `button`, `address` | Требования, обязанности, условия, формат работы и этапы найма должны быть структурированы; quick facts panel через `dl`. |
| Реквизиты | Юридические данные | `main` + legal facts block | `dl`, `section`, `address`, `time` | Это почти идеальный кейс для `dl`; все юридические параметры должны быть парами “поле–значение”. |

## Персоналии и эксперты

| Тип страницы | Основная роль | Базовый semantic skeleton | Обязательные/сильные теги | Упущенные возможности и лучшие приемы |
|---|---|---|---|---|
| Профиль автора | Подтверждение авторства и квалификации | `main` + author `article` + bio sections | `article`, `header`, `figure`, `dl`, `section`, `time`, `address` | Полезно структурировать опыт, специализацию, публикации, роли, достижения; краткий fact-pack повышает E-E-A-T сигналы страницы. |
| Страница команды | Коллекция экспертов | `main` + intro + list из person `article` | `article`, `figure`, `figcaption`, `dl`, `section` | Каждого специалиста лучше делать самостоятельной сущностью, а не просто карточкой с фото; можно выделять направления экспертизы и сертификаты. |
| Профиль сотрудника | Биография и достижения | `main` + person `article` + profile sections | `article`, `header`, `figure`, `dl`, `section`, `blockquote`, `time`, `address` | Хорошо работают секции “специализация”, “опыт”, “проекты”, “сертификаты”, “публикации”, “выступления”; достижения и факты — через `dl` и списки. |

## Приоритеты по типам страниц

## Самые критичные для `article`

- карточка товара,
- услуга,
- статья,
- кейс,
- вакансия,
- отзыв,
- профиль автора,
- профиль сотрудника,
- видеоэлемент,
- элемент портфолио.

## Самые критичные для `dl`

- карточка товара,
- страница услуги,
- кейс,
- вакансия,
- реквизиты,
- словарь,
- профиль автора,
- профиль сотрудника,
- брендовые и юридические quick facts.

## Самые критичные для `table`

- сравнение товаров,
- прайс-лист,
- тарифы,
- матрицы совместимости,
- размерные сетки,
- SLA,
- расчетные сводки.

## Самые критичные для `time`

- новости,
- акции,
- кейсы,
- вакансии,
- статьи,
- страницы с условиями и сроками,
- программы лояльности,
- сертификаты,
- страницы с обновляемыми регламентами.

## Самые критичные для `details/summary`

- FAQ,
- юридические пояснения,
- расширенные характеристики,
- документация,
- вторичные help-блоки.

## Финальная логика выбора

Если страница:

- продает — сначала сущность, ее параметры, выгоды, ограничения, доказательства;
- объясняет — сначала определение, затем структура, шаги, примеры, ограничения;
- сравнивает — сначала критерии сравнения, затем table;
- подтверждает доверие — сначала идентичность, факты, документы, контакты, история;
- представляет человека — сначала роль, экспертиза, опыт, достижения, публикации.

Семантика должна следовать не дизайну, а намерению страницы и типу извлекаемых фактов.
