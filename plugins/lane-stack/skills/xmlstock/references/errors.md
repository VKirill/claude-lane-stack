# xmlstock — Error codes

xmlstock возвращает ошибки в двух режимах:
1. **HTTP 200 с тегом `<error>`** в XML/JSON-ответе — стандартная программная ошибка.
2. **HTTP не 200** — ошибка сервера, ответ не обработан.

## HTTP-200 ошибки (тег `<error>`)

```xml
<?xml version="1.0" encoding="UTF-8"?>
<yandexsearch version="1.0">
  <response date="20250301T105416">
    <error code="210">Запрос поставлен в очередь...</error>
  </response>
</yandexsearch>
```

## Не-HTTP-200 ошибки

| HTTP | Описание | Что делать |
|:-:|---|---|
| 500-502 | Внутренняя ошибка сервера xmlstock | Retry с exponential backoff (2 → 4 → 8 с) |
| 503 | Превышен RPS на стороне сервера xmlstock | Backoff, снизить concurrency до рекомендованной |
| 504 | Gateway timeout (CDN/прокси) | Retry |
| 408 | Request Timeout | Retry, проверить таймауты клиента |

**Деньги за такие запросы не списываются.**

## Декодирование ошибок в клиенте

```python
import xml.etree.ElementTree as ET

def parse_response(xml_bytes: bytes):
    root = ET.fromstring(xml_bytes)
    error = root.find(".//error")
    if error is not None:
        code = int(error.get("code"))
        text = error.text or ""
        return {"error": True, "code": code, "text": text}
    return {"error": False, "data": root}
```

## Retry-стратегия — таблица решений

| Код | Retry? | Stratagy |
|:-:|:-:|---|
| 1, 2, 3-14/3-10/3-9, 18 (валидация), 19, 37, 10001, 10002 | ❌ | Это баг параметров, retry не поможет |
| 15 | ❌ | Пустая SERP, retry бесполезен |
| 20, 20-25, 110, 300 | ✔ | Exponential backoff 2 → 4 → 8 → 16 с, max 5 попыток |
| 31, 42, -34 | ❌ | Проверить креды, retry без исправления бесполезен |
| 32 | условно | Дождаться суточного сброса или поднять лимит — потом возобновить |
| 55 | ✔ | Backoff с jitter, снизить concurrency |
| 101 | условно | Ждать восстановления (10-60 минут), затем возобновить |
| 200 | ❌ | Остановить воркер, ждать пополнения баланса |
| 201 | ✔ | Подождать 30 с (cooldown кеша), затем 1 retry |
| 202 | ✔ | Polling 20-30 с, до получения SERP или 203 |
| 203 | ✔ (re-submit) | Заново `delayed=1` (новое списание!) |
| 210 | ✔ | Retry тот же URL через 20-30 с, до получения SERP |
| HTTP 500-502 | ✔ | Backoff 2 → 4 → 8 с, max 5 попыток |
| HTTP 503 | ✔ | Снизить concurrency, backoff с jitter |

## Идемпотентность

- Hybrid retry того же URL — идемпотентен (xmlstock запомнил задачу).
- Async retry с **тем же** `req_id=...` — идемпотентен.
- Async **повторная** отправка `delayed=1` без persist `req_id` — **не идемпотентна**, создаёт новую платную задачу.
- Hybrid с разными `page=`, `lr=`, `domain=`, `device=` — разные задачи, каждая тарифицируется отдельно.

## Что логировать

- Полный URL запроса (с замаскированным ключом).
- HTTP-код, длительность.
- `error code` и `error text`.
- `req_id` (если async).
- Хэш ключа задачи (`engine|query|lr|domain|device|page|tbm`).
- Балансовое состояние (если есть способ узнать).
