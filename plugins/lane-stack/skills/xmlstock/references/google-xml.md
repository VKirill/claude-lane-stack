# Google XML Search (xmlstock google/{xml,json,html})

Эндпоинт: `https://xmlstock.com/google/{xml|json|html}/`

JSON и HTML доступны во всех режимах. HTML удобен, когда нужно распарсить блоки, которые xmlstock не отдаёт в структурированном виде.

**С учётом ограничения Google: 10 результатов на странице.** Параметр `groupby` больше не действует.

## Полный список GET-параметров

| Параметр | Обяз. | Описание |
|---|:-:|---|
| `user`, `key`, `query` | ✔ | Стандартные |
| `lr` | | Регион. Передаётся либо Google-ID региона (см. csv в документации), либо ID региона Яндекса — xmlstock автоматически сопоставит (по запросу в техподдержку для конкретного аккаунта). |
| `page` | | Номер страницы (0-based) |
| `start` | | Альтернатива `page`: первая позиция результата (например `start=50` для страницы 6) |
| `domain` | | Зона Google: `com` (default), `ru`, `com.ua`, `by`, и т.д. Можно числовое значение (`143` = google.ru) |
| `device` | | `desktop` / `mobile` |
| `tbm` | | Тип поиска: `` (default — органика), `images`, `news`, `video` |
| `tbs` | | Период поиска (см. ниже) |
| `hl` | | Язык интерфейса пользователя (`ru`, `en`, `uk`, ...) — влияет на ранжирование и точность результатов |
| `ads` | | `1`=показать рекламные блоки. **Не работает для РФ** (санкции Google) — параметр сохранён для совместимости |
| `related` | | `1`=показать одновременно Related Questions (PAA) и Related Searches |
| `filter` | | `1`=включить скрытые "very similar" результаты |
| `punycode` | | `1` / `0` |
| `hlword` | | `1`=обернуть ключевые слова `<hlword>...</hlword>`; `0`=нет |
| `nfpr` | | `1`=без исправления опечаток (поиск по точному вхождению); `0`=исправлять (default) |
| `safe` | | `` (пусто=blur, default) / `on`=фильтр / `off`=всё показывать |

## Параметр `tbs` — период поиска

| Значение | Смысл |
|---|---|
| (не задан) | За всё время (default) |
| `qdr:s` | За секунду |
| `qdr:n` | За минуту |
| `qdr:n10` | За 10 минут (число после `n`/`h`/`d` варьируется) |
| `qdr:h` | За час |
| `qdr:d` | За 24 часа |
| `qdr:w` | За неделю |
| `qdr:m` | За месяц |
| `qdr:y` | За год |
| `cdr:1,cd_min:1/2/2023,cd_max:3/2/2023` | Конкретный диапазон дат (формат `M/D/YYYY`) |

## Парсинг картинок (`tbm=images`)

```
&tbm=images&gl=ru&query=окна
```

- Некоторые стандартные параметры **не** работают для картинок (например паджинация и тонкая региональность).
- Страну поиска — `gl=ru` (Google-style geo).
- Язык интерфейса — `hl=ru`.

## Парсинг новостей (`tbm=news`)

```
&tbm=news&gl=ru&query=новости
```

- Только Google.
- `gl=` для страны, `hl=` для языка UI.

## Парсинг видео (`tbm=video`)

```
&tbm=video&gl=ru&query=окна
```

## Related (PAA + Related Searches)

```
&related=1&query=seo
```

Активирует **оба** блока в Google: People Also Ask (Вопросы по теме) и Related Searches (Запросы по теме). Эти блоки активируются одним флагом — раздельно не отделяются.

## Filter (скрытые результаты)

```
&filter=1&query=окна
```

По умолчанию Google скрывает "very similar" результаты. С `filter=1` они включаются в выдачу.

## Регионы — сопоставление с Яндексом

xmlstock умеет принимать `lr=` в формате Яндекса (например `lr=213` для Москвы) и сам сопоставит с регионом Google. Это удобно для кросс-движкового мониторинга: один и тот же `lr` для обоих движков.

**Активация сопоставления — запрос в техподдержку xmlstock на конкретный аккаунт.**

Без сопоставления — использовать стандартный Google `lr=` (csv-файл идентификаторов в документации xmlstock) либо `gl=` / `hl=` для `tbm=images`/`news`/`video`.

## Структура ответа (XML, упрощённо)

```xml
<googlesearch>
  <response date="...">
    <found-docs>...</found-docs>
    <results>
      <doc id="...">
        <url>...</url>
        <domain>...</domain>
        <title>...</title>
        <passages>
          <passage>...</passage>
        </passages>
      </doc>
      ... (10 шт)
    </results>
    <related-questions>
      <question>
        <text>...</text>
        <answer>...</answer>
        <source-url>...</source-url>
      </question>
      ...
    </related-questions>
    <related>
      <query>...</query>
      ...
    </related>
  </response>
</googlesearch>
```

Точные имена тегов могут отличаться — сверяйся с актуальным ответом xmlstock.

## JSON-режим

Эндпоинт `google/json/` отдаёт ту же информацию в JSON. Удобен для интеграций, не желающих парсить XML.

## HTML-режим

Эндпоинт `google/html/` отдаёт сырую страницу Google. Подходит, когда нужно вытащить нестандартные SERP-фичи (Knowledge Graph, Featured Snippets с разметкой, локальные карточки). Парсить нужно самостоятельно (BeautifulSoup / Cheerio).

## Особенности

- `ads=1` не работает для РФ — Google отключил рекламу из-за санкций. Параметр оставлен для совместимости, но возвращает пустые блоки.
- `groupby` устарел из-за 10-результата cap'a Google.
- Для очень глубокой паджинации (>10 страниц) Google может вернуть менее точные результаты — Google сам по себе ограничивает глубину выдачи.
- `safe` без значения = blur (картинки замазаны, текст/ссылки остаются), `safe=on` — полный фильтр, `safe=off` — без фильтра.

## Cost-conscious patterns

- Не запрашивать одну и ту же связку `(query, lr, domain, device)` повторно — TTL смены SERP большой, кэшировать у себя на 6-24 часа норм.
- Для мониторинга позиций — собирать только нужные страницы (если позиция уже найдена в ТОП-10, не запрашивать страницу 2).
