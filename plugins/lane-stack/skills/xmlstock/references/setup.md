# xmlstock — Setup и базовая модель запросов

## Эндпоинты

| Engine | URL | Форматы |
|---|---|---|
| Яндекс Search API (XML) | `https://xmlstock.com/yandex/xml/` | только XML |
| Яндекс Live | `https://xmlstock.com/yandexlive/xml/` | XML |
| Яндекс Live | `https://xmlstock.com/yandexlive/json/` | JSON |
| Яндекс Live | `https://xmlstock.com/yandexlive/html/` | HTML (только в `tbm=turbo`) |
| Google XML Search | `https://xmlstock.com/google/xml/` | XML |
| Google XML Search | `https://xmlstock.com/google/json/` | JSON |
| Google XML Search | `https://xmlstock.com/google/html/` | HTML |

JSON-ответ доступен для Live и Google, **не** для Яндекс XML. HTML для Live — только в `tbm=turbo` (тарифицируется отдельно).

## Аутентификация

Передаётся в query-string:

```
?user=<your_user_id>&key=<your_api_key>
```

- `user` — числовой ID пользователя в системе xmlstock.
- `key` — API-ключ, виден в личном кабинете, можно ротировать в любой момент. После ротации старый ключ перестаёт работать сразу.

**Безопасность:** ключ в URL уходит в access-логи прокси/CDN. Желательно держать клиента на доверенной машине; для распределённого скрапинга — собственный mTLS прокси или подписанные query-параметры внутри инфры.

## Параметры по умолчанию

В личном кабинете xmlstock есть раздел **Настройки**, где задаются дефолтные `lr`, `domain`, `device`, `filter`, `groupby` и т.д. **Параметры в URL имеют приоритет** над дефолтами. Если параметр не передан, берётся значение из ЛК.

**Recommendation:** в production-коде **всегда явно передавать** `lr`, `domain`, `device`, `groupby` (для Яндекс XML) — иначе смена дефолтов в ЛК молча сломает выдачу.

## Тарифные планы

- **Базовый** — оплата за каждый запрос (поштучно). Это default.
- **Оптимальный / Максимум** — пакетные тарифы для больших объёмов; цена ниже. Подключаются в ЛК.

Цена на Яндекс XML инструмент **одинакова на всех тарифных планах** (это особенность Яндекса).

Для оптовых клиентов возможна индивидуальная цена ниже базовой 18 руб/1000 — обсуждается с техподдержкой.

## Биллинговая модель — ключевые правила

1. **Списание происходит при первой отправке запроса в API**, независимо от того, был ответ получен сразу или поставлен в очередь (hybrid 210 / async req_id).
2. **Re-fetch по тому же req_id** (async) или повторный hybrid-запрос с теми же параметрами при 210 — **бесплатны** (xmlstock запоминает задачу).
3. **Тарифицируемые ошибки**: 1 (синтаксис query), 15 (ничего не найдено), 18 (невалидный XML body или page>250), 19 (несовместимые параметры), 37 (ошибка в параметрах), 10001/10002 (слишком длинный query), 210 (поставлено в очередь — для Яндекс XML async и hybrid).
4. **Не тарифицируемые ошибки**: всё остальное (32, 55, 200, 201, 202, 203, -34, 42, 31, 101, 110, 500-503).
5. Нет публичного `/balance` endpoint — мониторинг баланса через личный кабинет или путём отлова `error 200` ("На вашем счету закончились деньги").

## Тестовый запрос

```
https://xmlstock.com/yandex/xml/?user=11396&key=b3c2f28ec0a90b44e486af55c2f6b270&query=окна
```

(пример из документации — заменить на свои `user`/`key`)

Минимальный успешный ответ Яндекс XML:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<yandexsearch version="1.0">
  <response date="20250301T105416">
    <results>
      <grouping ...>
        <group>
          <doc>
            <url>https://example.com/window</url>
            <title>...</title>
            <passages>...</passages>
            <domain>example.com</domain>
          </doc>
        </group>
        ...
      </grouping>
    </results>
  </response>
</yandexsearch>
```

## Ротация ключа

В ЛК `→ Настройки → Изменить ключ`. Старый отзывается **сразу**. План ротации:
1. Сгенерировать новый ключ.
2. Деплой кода/конфига с новым ключом.
3. Проверить, что воркер пишет 2xx с новым ключом.
4. Отозвать старый.

## Encoding

Все ответы — `UTF-8`. Запросы (особенно с кириллицей) — обязательно URL-encoded UTF-8. Передача в неверной кодировке приводит к `error 1` (синтаксис query).

## GET vs POST

- GET — лимит на длину URL ~8KB (зависит от прокси). Для типичных задач этого хватает.
- POST с XML-телом — обязателен для:
  - Сложных группировок (`groupby` с deep-attr) в Яндекс XML,
  - Запросов с длинным `query` близко к 400 символов,
  - Запросов в неподходящих контекстах (если CDN режет длинные URL).

POST-формат описан в `yandex-xml.md`.

## Личный кабинет — что мониторить

- **Статистика запросов** — `Статистика запросов` в ЛК: запросы, успехи, ошибки, остаток баланса.
- **Суточный лимит** — задаётся в ЛК (`error 32` сигнализирует о превышении).
- **Активные API-ключи** — отзыв, ротация.
