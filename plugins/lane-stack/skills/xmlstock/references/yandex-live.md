# Яндекс Live (xmlstock yandexlive/{xml,json,html})

Эндпоинт: `https://xmlstock.com/yandexlive/{xml|json|html}/`

- XML — основной формат, поддерживает все параметры включая `within=`.
- JSON — все параметры включая `within=`.
- HTML — только в `tbm=turbo` (доп. тарификация).

**1 запрос = 10 результатов** (фиксированный лимит живой выдачи, паджинация через `page=`).

## Полный список GET-параметров

| Параметр | Обяз. | Описание |
|---|:-:|---|
| `user`, `key`, `query` | ✔ | Стандартные |
| `lr` | | Регион ранжирования |
| `page` | | Номер страницы (0-based) |
| `domain` | | `ru` (default), `by`, `kz`, `com.tr` |
| `device` | | `desktop` (default) / `mobile` |
| `tbm` | | Тип поиска: `` (default — органика), `images`, `video`, `turbo` (HTML, доп. оплата) |
| `tbs` | | (в Live не упомянуто; используется в Google) |
| `lang` | | Поиск сайтов по конкретному языку: ru / en / be / id / kk / de / tt / tr / uk / fr |
| `rstr` | | Поиск по сайтам с упоминанием региона: `rstr=-213` (Москва), синтаксис со знаком минус, аналогично `lr` |
| `within` | | Период (только XML/JSON): `77`=за сутки, `1`=за 2 недели, `2`=за месяц |
| `ads` | | `1`=показывать топ+нижний рекламные блоки Яндекс.Директ; `0`/не задан=нет |
| `scroller` | | `1`=показывать товарную карусель (часто бывает по коммерческим запросам); `0`=нет |
| `related` | | `1`=показывать "Люди ищут" (Related Searches) внизу страницы; `0`=нет |
| `punycode` | | `1`=кириллические домены в Punycode; `0`=в кириллице |
| `hlword` | | `1`=выделять ключевые слова тегом `<hlword>`; `0`=нет |
| `noreask` | | `1`=без исправления опечаток; `0`=исправлять (default) |

## Поисковые операторы в `query`

Те же, что в Яндекс XML (`site:`, `mime:`, `lang:`, `date:`), плюс **`image:URL`** — обратный поиск по картинкам, работает **только** в режиме `tbm=images`.

## Парсинг картинок (`tbm=images`)

```
https://xmlstock.com/yandexlive/xml/?user=...&key=...&query=окна&tbm=images
```

- Возвращает **30 результатов** на страницу.
- Поддерживает паджинацию (`page=`).

### Обратный поиск (Reverse Image Search)

```
&tbm=images&query=image:https://xmlstock.com/window.jpg
```

В ответе:
1. Блок "Другие размеры изображения".
2. До 20 результатов из блока "Сайты с информацией про изображение".

## Парсинг видео (`tbm=video`)

```
&tbm=video&query=окна
```

Возвращает 18 результатов на страницу, паджинация работает.

## Парсинг рекламы Яндекс.Директ (`ads=1`)

Возвращает данные из топового и нижнего рекламных блоков. По каждому объявлению:
- адрес сайта,
- заголовок,
- текст,
- телефон (если есть),
- ссылка на профиль организации в Яндексе,
- город / станция метро,
- название организации и ИНН (прямой рекламодатель или рекламное агентство).

Если поля нет в объявлении — оно не выводится.

```
&ads=1&query=окна
```

## Товарная карусель (`scroller=1`)

Карусель с товарами вверху страницы (типично для запросов "купить ...", электроники, бытовой техники). Чувствительна к региону и тематике — не во всех запросах есть.

По каждому товару:
- адрес сайта (магазина),
- зашифрованная ссылка на товар,
- название,
- изображение,
- цена,
- название и ИНН организации.

```
&lr=213&scroller=1&query=купить iphone
```

Можно сочетать с `ads=1`.

## Related Searches (`related=1`)

Блок "Люди ищут" внизу страницы. Возвращает похожие запросы пользователей. Возвращается при наличии блока в SERP.

```
&related=1&query=окна
```

## Turbo-режим (`tbm=turbo`)

- Возвращает HTML страницы выдачи (для парсинга всего, что нет в XML/JSON).
- Тарифицируется отдельно (выше базовой ставки).
- Минимальный rate ошибок, выше скорость.
- Для retry: код `202` означает "ещё обрабатывается, повторить через 10-20 секунд".

## Period фильтр `within=` (XML/JSON only)

| Значение | Период |
|---|---|
| `77` | За последние сутки |
| `1` | За 2 недели |
| `2` | За месяц |

**Не работает в HTML/Turbo формате.** Для HTML использовать оператор `date:` в `query`.

## Особенности

- В картинках/видео некоторые стандартные параметры (паджинация в "image:reverse" не работает за пределами первой страницы, региональность для `tbm=images` слабее) — подробности в актуальной справке xmlstock.
- `lang` и `rstr` — расширенные операторы, использовать аккуратно: они меняют корпус документов в выдаче, можно получить пустую SERP.
- В Яндекс Live `groupby` **не** поддерживается — структура SERP фиксирована живой выдачей.
- Подавляющее большинство rate-проблем — превышение 10 одновременных потоков. Сохраняй concurrency на 10 или ниже, либо договаривайся с поддержкой.

## Пример ответа (XML, с дополнительными блоками)

Упрощённо:

```xml
<yandexsearch>
  <response date="...">
    <topads>
      <ad>
        <url>...</url>
        <title>...</title>
        <text>...</text>
        <phone>...</phone>
        <organization>...</organization>
        <inn>...</inn>
        ...
      </ad>
      ...
    </topads>
    <scroller>
      <product>
        <url>...</url>
        <title>...</title>
        <image>...</image>
        <price>...</price>
        <organization>...</organization>
        <inn>...</inn>
      </product>
      ...
    </scroller>
    <results>
      <doc>...</doc>
      ... (10 шт.)
    </results>
    <related>
      <query>...</query>
      ...
    </related>
    <bottomads>
      <ad>...</ad>
      ...
    </bottomads>
  </response>
</yandexsearch>
```

Точная структура тегов может отличаться — сверяться с реальным ответом и xmlstock-документацией.
