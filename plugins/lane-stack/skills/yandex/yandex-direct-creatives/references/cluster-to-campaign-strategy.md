# Стратегия: от кластеров CSV к структуре Яндекс Директ

> Этот файл описывает **стратегию группировки** кластеров в кампании и группы Direct.
> КАК читать CSV — см. `csv-workflow.md`.
> Шаблоны текстов объявлений — см. `composition-templates.md`.

---

## 1. Таблица решений: 1 кампания = 1 кластер vs N кластеров

| Сценарий | Решение | Почему |
|---|---|---|
| Разные офферы (курс vs репетитор) | 1 кампания = 1 кластер | Разные landing'и, разные бюджеты, разный A/B |
| Разные landing'и для одного оффера | 1 кампания = 1 кластер | Каждый landing — отдельный URL в объявлении |
| Разные бюджеты для разных групп слов | 1 кампания = 1 кластер | Direct управляет бюджетом на уровне кампании |
| Один оффер, один landing, разные вариации | 1 кампания = N кластеров | Группы внутри одной кампании, общий бюджет |
| Брендовые + общие запросы того же оффера | 1 кампания = N кластеров (отдельные группы) | Брендовые дешевле + защита от конкурентов |
| Геотаргетинг разный (Москва vs регионы) | 1 кампания = 1 гео | Direct позволяет гео только на уровне кампании |

**Практическое правило:** если у двух кластеров разные landing'и или разные бюджеты — это разные кампании. Если всё одно — разные группы внутри одной кампании.

## 2. Соглашения по именованию

### Кампании

Формат: `[intent]_[geo]_[product]`

| Сегмент | Допустимые значения | Пример |
|---|---|---|
| intent | `transactional`, `informational`, `branded`, `navigational` | `transactional` |
| geo | `msk`, `spb`, `ru` (вся Россия), `reg` (регионы) | `msk` |
| product | короткое название продукта, kebab-case | `repetitor`, `excel-courses` |

Примеры:
- `transactional_msk_repetitor`
- `informational_ru_excel-courses`
- `branded_msk_skyeng`

### Группы

Формат: `[cluster_id]_[marker]`

- `cluster_id` — числовое значение поля «Кластер» из CSV. Это **главный стабильный ID**.
- `marker` — укороченная форма «Маркерного запроса», kebab-case, не более 30 символов. Убираем стоп-слова, транслитерация не нужна.

Примеры (из `test_direct.csv`):
- `1_stobalniy-repetitor`
- `2_100ball-online`
- `15_ege-russkiy-online`

**Важно:** имя группы не должно меняться после создания — по нему восстанавливается связь кластер → объявление в feedback loop.

## 3. Стабильные ID для Phase 3.5.C feedback loop

Когда Direct модерация возвращает REJECTED с per-item ошибками, нужно понять: «какой исходный кластер → какой шаблон → какой вариант дал отказ».

### Схема ID

- **`cluster_id`** — берётся из поля «Кластер» CSV. Идёт в имя группы Direct.
- **`ad_variant_id`** — 1, 2, 3 (порядковый номер варианта внутри группы). Идёт в debug-поле объявления.

### Как записывать

| Поле объекта Direct | Значение |
|---|---|
| Имя группы (AdGroupName) | `[cluster_id]_[marker]` |
| Debug-метка варианта | `var-[ad_variant_id]` (в текстовое поле, не в tracking-параметры) |

### Зачем это нужно

Direct API при ошибке модерации возвращает `AdId` — уникальный ID объявления. Без `cluster_id` и `ad_variant_id` в имени / debug-поле агент не сможет восстановить «какому кластеру принадлежало это объявление» после пакетной загрузки 390+ объявлений.

## 4. Минимальное и рекомендуемое число объявлений на группу

| Кол-во объявлений | Оценка | Комментарий |
|---|---|---|
| 1 | Нельзя | Нет A/B, нет резерва при отклонении модерацией |
| 2 | Слабо | Минимальный A/B, один отказ — и группа без показов |
| **3** | **Рабочая база** | 1 базовый + 1 альтернативный + 1 экспериментальный |
| 4–5 | Рекомендуется | Для зрелой группы с историей A/B |
| > 5 | Избыточно | Direct ротирует медленнее — лучше создать дополнительную группу |

**Дефолт при генерации:** 3 объявления на группу. Шаблоны трёх вариантов — в `composition-templates.md`.

## 5. Вывод минус-слов из не-целевых intent

Строки CSV с разным полем «Тип» (intent) внутри одного кластера — источник минус-слов.

### Принцип

- Основная кампания `transactional` → строки с `informational` из того же кластера дают кандидатов в минус-слова.
- Основная кампания `informational` → строки с `transactional` дают кандидатов в минус-слова.

### Пример на test_direct.csv

**Кластер 1** («стобальный репетитор онлайн школа») — большинство строк `informational`.

- Если делать `transactional`-кампанию (целевой intent — «купить/заказать/цена»):
  - Минус-слова из информационных запросов: «что такое», «как», «бесплатно», «отзывы», «форум»
- Если делать `informational`-кампанию (контент, обзоры):
  - Те же слова — целевые. Минусуем коммерческие: «купить», «цена», «стоимость», «заказать»

### Правило оптимизации

**Не дублируй минус-слова между группами внутри одной кампании.** Direct поддерживает минус-слова на уровне кампании — общие минусы выноси туда, группо-специфичные оставляй в группе.

## 6. Batch-risk и canary

130 кластеров × 3 объявления = **390 креативов** в одной волне. Один кривой шаблон может уронить всю партию через несколько часов модерации.

### Правило canary (обязательно при ≥ 100 кластеров)

1. Загрузить **5–10% первых кластеров**: для 130 кластеров = 13 кластеров × 3 ads = ~40 объявлений.
2. Дождаться **полной модерации** (все статусы ACCEPTED или REJECTED).
3. Оценить процент REJECTED:

| Процент REJECTED | Действие |
|---|---|
| < 10% | Норма — заливать остальное |
| 10–30% | Переписать проблемные шаблоны, перезалить canary |
| > 30% | **СТОП** — разобрать причины с человеком, пересмотреть `composition-templates.md` |

### Hard cap и chunking

- **≤ 100 объявлений за раз.** При превышении — chunking: делим на части по 100.
- Phase 3.5.C обязана резервировать units Direct и останавливаться при достижении лимита.

### Post-factum revoke

Direct может **отозвать ACCEPTED** через несколько часов или дней после первоначального одобрения (автоматические проверки, жалобы, ручная проверка). Phase 3.5.C должна поллить статусы объявлений **минимум раз в день в течение первой недели** после загрузки.
