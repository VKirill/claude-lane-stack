# Длина текста и читабельность

## Рекомендуемая длина под типы запросов

Нет универсальной «правильной длины». Длина определяется типом запроса и тем, что нужно пользователю.

### Информационные запросы (lonread)

**«Как сделать», «что такое», «почему», «руководство», «гайд»**

Ориентир: 1 500–3 000+ слов

Обоснование:
- Пользователь хочет полный ответ, не резюме
- Google оценивает «глубину покрытия темы» (через анализ конкурентов)
- Чем сложнее тема — тем длиннее должен быть ответ

Примеры:
- «Как настроить рекламу ВКонтакте с нуля» → 2 500–3 500 слов
- «Что такое ипотека на вторичку и как её получить» → 2 000–2 500 слов
- «История основания Москвы» → 1 500–2 000 слов

### Коммерческие / транзакционные запросы (short)

**«Купить», «заказать», «цена», «стоимость», «услуги»**

Ориентир: 300–700 слов на основном контенте страницы

Обоснование:
- Пользователь уже решил купить — ему нужны условия, а не лекция
- Длинный текст на лендинге отвлекает от CTA
- Но полное отсутствие текста — тоже плохо: нет сигналов для поисковика

Что включить в 300-700 слов:
- H1 с ключом
- Краткое описание услуги / продукта (1-3 абзаца)
- Условия / характеристики (список)
- Блок «почему мы» или преимущества (список)
- FAQ (3-5 вопросов)
- CTA

### Сравнительные запросы

**«X vs Y», «лучшие», «топ», «какой выбрать»**

Ориентир: 1 000–2 000 слов

Обоснование:
- Нужны таблицы сравнений, плюсы/минусы, вывод
- Достаточно полный, но не академически длинный

### Локальные и навигационные запросы

**«стоматология метро Аэропорт», «суши Екатеринбург»**

Ориентир: 200–500 слов + структурированные данные

Обоснование:
- Пользователь ищет адрес / телефон / часы работы
- Длинный текст — лишний
- Важнее: schema.org/LocalBusiness, карта, отзывы

## Как считать «достаточную глубину»: анализ топ-10

**Алгоритм:**

1. Введи целевой запрос в Google/Яндекс
2. Открой топ-10 результатов (не считая видео, картинки, агрегаторы)
3. Посмотри примерную длину каждой страницы:
   - Плагин Word Count (Chrome): считает слова на странице
   - Или скопируй текст в Word / Главред
4. Вычисли среднее по топ-10 → это ориентир минимума
5. Добавь 10-20% сверх среднего — не чтобы «быть длиннее», а чтобы покрыть аспекты, которые конкуренты упустили

**Важно:** не наполняй текст «водой» ради длины. Поисковики оценивают информационную плотность, а не количество символов. Повторение одного и того же разными словами снижает качество.

**Яндекс «Переспам»:** если текст раздут без смысловой нагрузки — Яндекс понижает позиции. Лучше 800 слов по делу, чем 2 000 с «водой».

**Google contentEffort:** из утечки API 2024 — сигнал оценивает «усилие» создания контента. Тонкие страницы без уникальных данных получают низкий score.

## Читабельность: принципы

### Короткие предложения

**Ориентир:** среднее предложение — 10-15 слов.

- До 10 слов — ударное, легко читается
- 10-20 слов — норма
- 20-30 слов — сложно, лучше разбить
- Более 30 слов — почти всегда можно разрезать

**Пример:**

Сложно:
> «При выборе ноутбука для учёбы необходимо учитывать несколько ключевых характеристик, в том числе мощность процессора, объём оперативной памяти, ёмкость аккумулятора, массу устройства и, конечно же, его стоимость, которая у разных производителей может существенно различаться.»
(47 слов)

Просто:
> «При выборе ноутбука для учёбы важны пять вещей: процессор, ОЗУ, автономность, вес и цена. Разбираем каждый пункт по порядку.»
(21 слово, два предложения)

### Ясный язык: избегать канцелярита

Канцелярит — это бюрократический язык, перегруженный отглагольными существительными и пассивными конструкциями.

**Признаки:**
- Цепочки существительных: «осуществление контроля за выполнением мероприятий»
- Пассивный залог без нужды: «было принято решение», «является необходимым»
- Вводные «водяные» конструкции: «в рамках данного вопроса», «следует отметить, что»

**Как исправлять:**

| Канцелярит | Живой язык |
|-----------|------------|
| «Осуществить оформление документов» | «Оформить документы» |
| «Является важным фактором» | «Важно» |
| «В целях повышения эффективности» | «Чтобы работало лучше» |
| «Было принято решение о переносе» | «Перенесли» |
| «На сегодняшний день» | «Сейчас» / «Сегодня» |
| «В данном случае» | «Здесь» / «В этом случае» |

**Инструменты проверки:**
- **Главред** (glvrd.ru) — анализирует канцелярит, «водяные» слова, оценивает текст по шкале до 10
- **Орфограммка** (orfogrammka.ru) — стиль + орфография
- **text.ru** — уникальность + читабельность

## Индексы читабельности: адаптация для русского

### Flesch-Kincaid (оригинал — для английского)

Флеш-Кинкейд в оригинальном виде не работает для русского языка — слоги, длина слов и синтаксис отличаются.

**Приблизительная адаптация:**
Чем меньше слов в предложении и слогов в словах — тем легче читается. Для русского это работает похожим образом, но пороговые значения другие.

**Ориентиры для русскоязычного текста:**
- Среднее предложение до 15 слов → легко читается
- Среднее предложение 15-20 слов → нормально
- Более 20 слов → тяжело

### Практический подход для русского

Вместо формул используй:

1. **Главред (glvrd.ru):** оценка 8+ из 10 = хорошая читабельность
2. **Тест «прочти вслух»:** если при чтении вслух хочется остановиться — предложение слишком длинное
3. **Тест «объясни ребёнку»:** если 12-летний не поймёт абзац — упрости
4. **Средняя длина предложения** (посчитать через Word): норма 12-16 слов для статьи, 8-12 для лендинга

### Fog Index (Ганнинг)

Fog = 0.4 × (слов/предложений + % «длинных слов»)

Для русского — тоже приблизительно, но принцип верный: больше коротких предложений и коротких слов = меньше «туман» = легче читается.

## Типичные ошибки

**1. «Добивать» объём бессодержательными абзацами**
Введение на 300 слов без единого факта, три абзаца-«воды» перед ответом на вопрос.
Исправление: начинай с сути. Читатель уже знает, что его интересует.

**2. Игнорировать тип запроса и писать всегда lonread**
Лендинг «купить диван» с 4 000 слов теории — пользователю нужна цена и кнопка заказа.
Исправление: анализируй интент перед написанием.

**3. Ориентироваться на «волшебное число» слов без анализа топа**
«Пишите 2 000 слов — этого достаточно для SEO». Для одной темы достаточно 800, для другой мало 3 000.
Исправление: смотри средний объём топ-10 по твоему конкретному запросу.

**4. Длинные цепочки канцеляризмов**
«В целях обеспечения максимального удобства пользователей сайта нами была проведена работа по оптимизации интерфейса.»
Исправление: «Мы упростили интерфейс, чтобы вам было удобнее.»

**5. Не адаптировать длину под мобильный**
На десктопе 3 000 слов выглядят нормально. На мобильном без хорошей структуры — это бесконечный скролл.
Исправление: короткие абзацы, заголовки через каждые 200-300 слов, списки вместо плотного текста.

**6. «Вода» в начале текста**
Первые 200 слов — история о том, как важна тема, общие рассуждения без пользы.
Поисковик и пользователь оценивают первый экран. Поздний ответ → высокий процент отказов.
Исправление: ответь на вопрос в первых 2-3 предложениях. Детали — ниже.

**7. Игнорировать мобильную читабельность**
Текст проверяли только на десктопе. На смартфоне абзацы по 8 строк в одну колонку — нечитаемо.
Исправление: тестируй финальный текст на мобильном.

## Источники

- Главред (glvrd.ru) — Максим Ильяхов, сервис проверки читабельности русских текстов
- Книга «Пиши, сокращай» — Максим Ильяхов, Людмила Сарычева (2016) — принципы ясного русского текста
- Rudolf Flesch «The Art of Readable Writing» (1949) — оригинальный индекс читабельности
- Robert Gunning «The Technique of Clear Writing» (1952) — Fog Index
- Google API Leak (май 2024): сигнал `contentEffort` — разбор Rand Fishkin / SparkToro (2024)
- Яндекс: алгоритм «Переспам» и рекомендации по качеству контента — официальная документация
- Moz: «Long-Form Content and Rankings» — исследование зависимости длины и позиций
