# Gate and revision rules

- A gate decides by code; a model's opinion alone never opens a gate.
- A failed gate names what to change; a retry that changes nothing is refused.
- Return 4→1 (execution back to discussion) or 5→2 (verification back to planning) is recorded with the reason and the context that changed.
- A revision of the plan after issue withdraws the pieces it no longer needs, it does not delete them.
- Three failed revisions of one gate stop the phase and ask the PM (or the owner with owner.words on).
